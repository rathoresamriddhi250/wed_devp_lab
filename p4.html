P4: GitHub README and Version Tags

Practical 4 · Documenting a project and marking a release

1) Open the README File

From the project directory, open the README file in the Nano text editor.

cd ~/dev-projects/bosscoder-module1
nano README.md

Write the following project introduction:

# Bosscoder Module 1 Portfolio

Built by Samriddhi Rathore, Bosscoder School of Technology covers terminal, Git & GitHub basics.

To save in Nano, press Ctrl + O, press Enter to confirm the filename, and press Ctrl + X to exit.

2) Commit and Push the README

Stage the README, commit the update, and push it to GitHub.

git add README.md
git commit -m "Add project README"
git push

3) Create and Push a Version Tag

Create a tag named v1.0 to mark this version, then push the tag to GitHub.

git tag v1.0
git push origin v1.0

4) Verify the Tag and Commit History

Use these commands to check the available tags and view the commit history with decorations.

git tag
git log --oneline --decorate

Note: Make sure your local branch is connected to the correct GitHub remote before pushing. A tag identifies a specific commit in the project history.

What I Learned

I learned how to write project documentation in a README file, commit and push the update, create a version tag, and verify the project history.
